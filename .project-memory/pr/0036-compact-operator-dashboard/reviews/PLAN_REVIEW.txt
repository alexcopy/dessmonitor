ROOT CAUSE ASSESSMENT

Root cause: "The dashboard layout reflects implementation order rather than
operator priority." — CONFIRMED.

The inverter section was added last (PR0034l) and placed at the bottom of the
page, below even Sensors. The first viewport shows generic counts (System Status,
Total Loads) that are less useful than inverter metrics. All loads are rendered
in one table with no active/inactive separation. No source indicator exists
despite working_mode and mains_status being available in every InverterReadSnapshot.

- All required data already flows through the pipeline (InverterReadSnapshot has
  working_mode, mains_status, and all voltage/power fields).
- The /control/state endpoint serializes inverter, loads, and sensors correctly.
- The dashboard receives the data but presents it in suboptimal order and format.

The plan preserves existing telemetry and contract semantics: no backend types
are modified, no new fields are added to any snapshot, no /control/state contract
changes occur.

Weather forecast is correctly deferred: the plan explicitly states weather
integration "is a separate data-source feature requiring backend ingestion
(OpenWeather API) and typed contract work" and excludes it from scope.
CONFIRMED: no weather data, no weather contract, no weather API in this plan.

SOURCE-INDICATOR ASSESSMENT

The plan defines a deterministic state mapping exclusively from existing
InverterReadSnapshot fields:

State         Trigger                                          Visual
"inverter"    working_mode in ("Battery Mode", "PV Mode",      Green badge
              "Invert Mode", "Power Saving Mode",              + battery/solar icon
              "Standby Mode", "Bypass Mode")

"mains"       working_mode == "Line Mode"                      Amber/blue badge
                                                                + lightning/plug icon

"fault"       working_mode == "Fault Mode"                     Red badge
                                                                + warning icon

"unknown"     Inverter array empty or working_mode == ""       Grey badge
                                                                + dash icon

This mapping uses ONLY controlled working_mode strings from the typed snapshot.
No device names, descriptions, or external heuristics. Each state maps to a
distinct CSS class (.source-indicator-inverter green, .source-indicator-mains
amber, .source-indicator-fault red, .source-indicator-unknown grey).

The source indicator is rendered as a compact badge/tag with a unicode character
and one word of text, set via textContent (not innerHTML). The unicode characters
used are: lightning bolt (⚡) for mains, sun (☀) or battery (🔋) for inverter,
warning sign (⚠) for fault, em dash (—) for unknown.

ACCEPTABLE: Deterministic, safe, and purely derived from existing typed fields.
