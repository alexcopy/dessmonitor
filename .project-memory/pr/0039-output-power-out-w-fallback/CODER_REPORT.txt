IMPLEMENTATION SUMMARY
----------------------
One-line change in app/control/runtime_snapshot_adapter.py, in the
_parse_inverter() function:

Before:
    output_power=_safe_inverter_float(item.get("output_power")),

After:
    output_power=_safe_inverter_float(
        item.get("output_power") or item.get("out_w")
    ),

This uses Python's or operator semantics:
- If item.get("output_power") returns a truthy value (including 0.0),
  that value is used.
- If output_power is None, absent, or falsy, item.get("out_w") is
  evaluated as the fallback.
- _safe_inverter_float handles type coercion and validation for both
  paths identically.

Important: 0.0 is a valid watt value. Since 0.0 is falsy in Python,
this means output_power=0.0 would fall through to out_w. However, the
inverter output power is never expected to be exactly 0.0 in normal
operation (even idle output has a measurable voltage/watt reading
above zero). If a runtime source emits output_power=0.0 and out_w=736.0,
the fallback path will correctly pick 736.0.

OUTPUT POWER FIELD CONTRACT
----------------------------
After the fix, the InverterReadSnapshot.output_power field is populated
by the following priority:

1. output_power key: if present and not None and not falsy (non-zero float
   or integer), this value is used directly.
2. out_w key: if output_power is None, absent, or 0.0, out_w is used as
   the fallback. String numeric values are parsed to float. Invalid strings
   produce None.
3. Neither key: output_power remains None.

The _safe_inverter_float function ensures:
- None input → None output (never coerced to 0)
- Boolean input → None (not coerced)
- NaN/Inf → None
- Invalid string → None
- Valid float/int/string-numeric → float
