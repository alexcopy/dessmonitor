CONTEXT
    BatteryChargeController remains the sole authority for charger-source
    requests, recovery thresholds, schedules, emergency handling and charger
    writes. Task 0080 is a pure shadow evaluator that reports a conservative
    Utility profile and never commands hardware. Task 0081/0082 expose that
    observation through the existing runtime/dashboard path. Task 0083 adds a
    separately authorized, one-way UtilityHoldCoordinator and a disabled live
    transport with durable intent, idempotency, readback and unresolved-outcome
    protection; it has no restore-to-SBU operation.

    Current runtime telemetry reports charger priority and output priority, but
    ordinary DESS telemetry is not independently verified setting readback.
    Runtime charge-policy status is not silently promoted to device readback.
    Therefore the default Task 0084 runtime result must remain shadow-only and
    blocked from a Utility write unless an explicitly injected, independently
    authorized UtilityHoldCoordinator receives the required fresh evidence.

    The design must coordinate existing capabilities, not create another
    charging controller, polling loop, reserve verifier, output-priority
    authority or SBU executor.

GOAL
    Implement the smallest coordination adapter that combines the existing
    Task 0080 shadow decision, fresh charger/output evidence and Task 0083's
    one-way Utility hold boundary without competing control loops.

    During confirmed or requested Solar + Mains recovery it must recommend or,
    only when a separately injected authorized executor is supplied, request
    one Utility hold. If evidence is incomplete, the safe result is a blocked
    Utility hold decision; emergency charging remains authoritative and is not
    delayed. When charging returns to Solar only, retain Utility until the
    existing Task 0076/0078 authority chain, post-recovery settling, dwell,
    anti-flap, manual-override and fresh setting evidence gates are satisfied.
    The current installation has no trusted reserve path, so automatic SBU
    restoration remains unreachable.

COORDINATION CONTRACT
    The new pure module must accept immutable inputs containing:
    - the Task 0080 CoordinationDecision and its exact current-snapshot-bound
      Task 0076/0078 recomputation inputs;
    - charger policy desired mode, observed mode, provenance and freshness;
    - output-priority reported/readback value, catalogue/readback provenance
      and freshness;
    - manual Utility/SBU override state;
    - emergency/recovery flags and current working mode;
    - an optional injected UtilityHoldCoordinator-like executor.

    A caller-reported positive decision is diagnostic-only. The adapter must
    not accept `verified`, `reserve`, `source`, `synthetic`, scalar or record
    fields as authority. Current Task 0078 unverified reserve forces the
    return side to remain blocked.

    The output must distinguish:
    - GRID_RECOVERY_REQUESTED: policy requests Solar + Mains but device
      readback is not yet verified;
    - UTILITY_HOLD: confirmed Solar + Mains with SBU or unknown output setting;
    - RECOVERY_SETTLING: charger release observed but post-recovery gates have
      not elapsed;
    - SOLAR_RETURN_BLOCKED: Solar-only charger state with weak PV, missing
      reserve, stale evidence, interlock hold, manual Utility or lockout;
    - SOLAR_RETURN_ELIGIBLE: advisory only, and unreachable with current 0078
      reserve authority;
    - SOLAR_OPERATION: not executable and unreachable in this task;
    - FAULT_HOLD: contradictory, unavailable, failed or unknown evidence;
    - MANUAL_OVERRIDE: operator hold takes precedence and no automatic change
      is attempted.

    Every result carries `shadow_only=True`, `command_issued=False`,
    `hardware_write_attempted=False` and `physical_transition_proven=False`.
    Emergency recovery has precedence over optional Utility coordination. A
    failed or unavailable output control path is reported but never blocks the
    charger controller's emergency tick.

EXECUTION ADAPTER CONTRACT
    The only permitted execution call is the existing Task 0083
    UtilityHoldCoordinator.hold(), supplied by dependency injection. Invoke it
    only after the pure decision requires Utility hold, the caller explicitly
    supplies the executor, and all Task 0083 evidence/authorization gates are
    passed. The adapter must never call LiveDessTransport directly, never call
    ctrlDevice, never retry an UNKNOWN/MISMATCH/INTENT result, and never expose
    restore-SBU. Already Utility is a zero-write no-op. The runtime path in
    this task supplies no executor, so production startup cannot write.

    Command ordering remains explicit: observe policy/readback, evaluate
    emergency and manual precedence, produce the shadow decision, then (only
    in an injected fake/authorized execution test) call UtilityHoldCoordinator
    once. Charger policy is not changed by this adapter. If the executor
    raises, times out or returns uncertain, retain Utility hold and surface the
    unresolved result without retry.

RUNTIME INTEGRATION
    Reuse the existing InverterMonitor observation and post-charge callbacks.
    Do not alter its polling interval or await a control request on the monitor
    path. run.py may construct the coordinator in shadow mode and pass it to
    WinterRuntimeDiagnostics. The diagnostic callback must remain failure
    isolated: a coordinator exception cannot prevent telemetry persistence,
    charger ticks or emergency handling.

    Runtime charge-policy status is labelled runtime status, not device
    readback. The current ordinary DESS output/charger fields remain
    unverified unless supplied through a separately verified observation object.
    The dashboard payload continues to show the result as diagnostics; no new
    control endpoint, UI command or production setting is added.

STATE AND ORDERING RULES
    - Active emergency recovery wins over all optional output coordination.
    - Manual Utility wins over solar-return consideration; manual SBU cannot
      bypass interlock, reserve, freshness, dwell or authorization gates.
    - Solar + Mains policy request without verified charger readback is
      GRID_RECOVERY_REQUESTED/FAULT_HOLD, never an execution authorization.
    - Verified Solar + Mains plus SBU output readback yields UTILITY_HOLD and a
      conflict diagnostic. If output is already Utility, no write is proposed.
    - A voltage rise during charging never advances return eligibility.
    - Solar-only charger state begins RECOVERY_SETTLING or
      SOLAR_RETURN_BLOCKED; it never immediately requests SBU.
    - Only the existing Task 0076/0078/0080 authority chain could produce a
      future advisory return. This task cannot produce battery-use eligibility
      or an SBU command.
    - Unknown, stale, contradictory, future or unavailable evidence fails
      closed. Restart begins in hold/fault unless durable existing authority
      explicitly reconstructs safe state; no automatic SBU follows restart.

TEST MATRIX
    Deterministic offline tests must cover:
    - Solar + Mains requested, output SBU, no verified charger readback:
      shadow hold/requested state, zero writes.
    - Confirmed Solar + Mains and verified SBU: one injected UtilityHold call,
      no duplicate call for repeated observation, and no charger-controller
      invocation.
    - Already Utility: zero-write no-op.
    - Battery voltage 25.5/26.0/27.0/28.0 V during charging: no return/SBU.
    - Solar-only with weak PV, missing/unverified reserve or post-recovery
      settling: Utility hold/blocked return.
    - Strong PV with a synthetic=False or otherwise caller-supplied reserve:
      still unverified and no positive return.
    - Existing Task 0076 churn lockout, stale/future/contradictory evidence,
      manual Utility and manual SBU requests.
    - Output readback mismatch/timeout, interrupted executor, UNKNOWN,
      MISMATCH, unresolved INTENT and restart: no retry and no SBU.
    - Emergency charging while output coordination is unavailable: emergency
      state wins and the charger input snapshot is unchanged.
    - Duplicate observations and repeated control requests are bounded.
    - Runtime observer failure isolation and disabled-by-default startup.
    - Static AST/import checks prove no new polling loop, ctrlDevice call,
      LiveDessTransport direct call, charger write or SBU executor.

    No migration, schema, persistent state store, deployment or production
    configuration is introduced. Rollback is removal/revert of the new adapter,
