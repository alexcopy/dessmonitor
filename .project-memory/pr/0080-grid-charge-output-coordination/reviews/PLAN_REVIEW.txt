A separate amendment is required before any runtime integration. This matches
the repository workflow and ADR-0001/ADR-0003 shadow-first requirements.

2. TASK 0076 EXACT SNAPSHOT BINDING — SATISFIED

The plan requires the future coordinator to construct one current
OutputTelemetry object, place that same object in InterlockSnapshot.telemetry
and InterlockEvaluationInputs.snapshot, assert exact object identity, and
invoke the existing evaluate_interlock with those inputs. A caller-reported
InterlockDecision is diagnostic-only; absent, stale, or mismatched authority
must produce INTERLOCK_SNAPSHOT_MISMATCH and cannot produce a positive state.
This preserves Task 0076 as the sole interlock authority and preserves its
current-snapshot recomputation contract.

3. TASK 0078 AUTHORITY AND RESERVE PROVENANCE — SATISFIED

The plan requires invocation of the unchanged winter evaluator from raw
EnergyInputs, ApprovedBands, WinterContext, WinterPolicyConfig, and the exact
snapshot-bound interlock inputs, with interlock=None. Therefore Task 0078's
own bound-interlock path recomputes Task 0076; a caller-supplied positive
WinterDecision is diagnostics-only and cannot authorize or promote the
coordinator. The plan explicitly rejects caller-controlled reserve,
synthetic, verified, source, scalar, and inspectable-record overrides.

The current absence of a trusted BMS/shunt integration is preserved as a
hard fail-closed boundary. A structurally valid synthetic=False reserve
fixture remains unverified, cannot yield BATTERY_USE_ELIGIBLE, cannot yield a
positive coordinator state, and is not used as a positive fixture. No new
trusted-source flag, certificate, token, or verification mechanism is
introduced. SOLAR_RETURN_CANDIDATE and SOLAR_OPERATION are unreachable for
current live inputs; any future trusted integration requires a separate
approved amendment and an exact raw-input evaluator call.

4. RECEIPT, MEASUREMENT, MODE, CYCLE, AND DUPLICATE SEMANTICS — SATISFIED

The plan makes the two time domains explicit and does not substitute receipt
time for an unverified device measurement time. Receipt continuity uses the
existing Task 0079 SAMPLE_GAP_SECONDS=600 constant: receipt times must be
strictly increasing, equal/decreasing/unknown times and gaps above 600 seconds
break the sequence, and a mode change across a break cannot count as a
transition or cycle. Measurement continuity remains governed by the supplied
Task 0076 baseline, including mode_continuity_max_gap_seconds and
max_telemetry_gap_seconds, with the existing inclusive comparisons.

A cycle is deterministic: one ordered sequence must contain a prior
recovery/grid-charge observation, an observed Invert interval, and a later
Line observation, with continuity under both receipt and measurement rules.
The Line observation closes the sequence; a later fresh recovery observation
starts the next one. Missing, stale, future, out-of-order, or unknown-time
samples cannot create a cycle. Duplicate payloads do not advance sequence
progress or settled-sample progress. The plan delegates mode-change counting,
failed-trial detection, escalation, lockout, and expiry to the existing Task
0076 semantics and explicitly forbids coordinator-only anti-flap constants or
a second lockout authority.

5. DWELL, SETTLING, CANDIDATE RESET, AND LOCKOUT — SATISFIED

The plan names and reuses the existing Task 0076 fields for failed-trial
limits, failed-trial lockout, mains and battery dwell, post-transition
settling, churn lockout, and maximum lockout. Candidate_since is precisely the
observed_at of the first current snapshot whose exact Task 0076 and Task 0078
raw-input evaluations are positive. It resets on invalid, stale, future,
unknown-time, contradictory, mode-continuity, or receipt-continuity evidence;
duplicates neither advance it nor count as settled samples. Promotion requires
existing post-transition settling, the existing settled-segment rule with its
minimum of three valid settled samples, and existing min_battery_dwell_seconds.
Current Task 0078 has no positive reserve authority, so this task implements
no live candidate/promotion path and emits no SOLAR_OPERATION result.

The deterministic priority order places emergency/protection, invalid or
unsafe evidence, existing lockout, active grid recovery, manual safety holds,
GRID_HOLD, candidate, and operation in the stated order. The acceptance matrix
requires exact boundary tests for receipt gaps, measurement gaps, mode-change
windows and limits, failed trials/escalation, dwell, settling, duplicates,
reset, and lockout expiry. This is sufficient to prevent a second
interpretation of Task 0076 anti-flap behavior.
