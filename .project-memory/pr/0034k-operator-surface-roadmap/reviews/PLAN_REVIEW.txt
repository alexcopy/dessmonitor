FIFTEEN-PR SEQUENCE ASSESSMENT

The PLAN defines exactly fifteen contiguous implementation PRs (PR0035-PR0049):

PR0035 — Redact Signed DESS Request Diagnostics
  Root cause: app/api.py logs/prints signed URLs with credentials (token, sign,
  salt, company-key, device identifiers). Confirmed at app/api.py lines 235, 238, 343.
  Scope: Redact signed URLs in log/print statements. Preserve safe diagnostic tokens.
  Out of scope: Tuya credential handling. ML collector logging.
  Security: Prevents DESS API credential leakage.

PR0036 — Runtime Heartbeat and Source Freshness Contract
  Root cause: runtime_state dict has no freshness metadata. Sources cannot declare
  their freshness independently.
  Scope: Add snapshot_created_at, runtime_heartbeat_at, devices_refreshed_at,
  inverter_refreshed_at timestamps. Each source declares freshness independently.
  Out of scope: Inverter read model. Sensor read model. Device status changes.

PR0037 — Typed Inverter Observability Snapshot
  Root cause: Inverter metrics exist only in shared_state. No typed snapshot.
  Scope: InverterReadSnapshot frozen dataclass. Written by InverterMonitor into
  runtime_state["inverter"]. Read by snapshot adapter.
  Dependencies: PR0036 (freshness timestamps inform inverter freshness).
  Out of scope: Dashboard rendering. Route-backed tabs. History/charts.

PR0038 — Canonical Inverter and Heartbeat Web Pipeline
  Root cause: Inverter and freshness contracts exist but no web pipeline.
  Scope: Complete end-to-end pipeline from InverterMonitor to dashboard.
  Dependencies: PR0036, PR0037.
  Out of scope: Route-backed tabs. Device-level changes. Sensor changes.

PR0039 — Route-Backed Bulma Tabs Shell
  Root cause: Single-page layout mixes all domains on one scroll surface.
  Scope: Six route-backed tabs using fetch() and DOM replacement. Active tab
  highlighted. URL path changes with tab selection.
  Dependencies: PR0038.
  Out of scope: Full content for every tab. Energy detail. Device detail.

PR0040 — System Health Overview
  Root cause: Overview tab exists as shell but content is old single-page layout.
  Scope: Health-first summary: heartbeat, inverter freshness, device/sensor
  freshness, battery, PV, warnings. No full device inventory.
  Dependencies: PR0038, PR0039.
  Out of scope: Energy detail. Devices tab. History tab. Charts.

PR0041 — Energy Detail Tab
  Root cause: Energy domain has no dedicated page.
  Scope: Full inverter detail with working mode, battery, PV, AC, output power,
  measured vs estimated vs derived consumption explicitly distinguished.
  Dependencies: PR0037+0038, PR0039.
  Out of scope: Historical charts. Sensor health. Device commands.

PR0042 — Active / Problems / All Devices Tab
  Root cause: Device table renders all devices regardless of state.
  Scope: Three sub-views: Active (confirmed ON first), Problems (stale/unhealthy/
  UNKNOWN), All (complete sorted). Active visible before OFF/unavailable.
  Dependencies: PR0039.
  Out of scope: Device commands. Device history. Configuration changes.

PR0043 — Sensor Health Tab
  Root cause: Sensors rendered below device table on one page.
  Scope: Dedicated Sensors tab with existing SensorReadSnapshot table.
  Dependencies: PR0039, existing sensor pipeline.
  Out of scope: Sensor configuration. Sensor history. Device state.

PR0044 — System Diagnostics and Structured Warnings
  Root cause: Startup reset, quarantine, warnings inline. No dedicated tab.
  Scope: System tab: startup reset status, polling quarantine, runtime uptime,
  source freshness, structured warning feed (no raw logs).
  Dependencies: PR0038+0039.
  Out of scope: Log files. Raw log display. Alerting. Notification.

PR0045 — Canonical Telemetry Consumers
  Root cause: MLDataCollector and DeviceStatusLogger still use shared_state["water_temp"]
  and ANALOG_TYPES/name-based classification instead of TelemetryRegistry and
  canonical device_type classification.
  Scope: All telemetry consumers read from canonical TelemetryRegistry. Use
  normalize_device_type and classify_projection_kind. Remove ANALOG_TYPES.
  Dependencies: PR0034j+0034h complete.
  Out of scope: shared_state removal. Inverter data migration.

PR0046 — Async Sensor Fallback Hardening
  Root cause: Individual-sensor-fallback uses run_coroutine_threadsafe().result()
  blocking the polling thread (confirmed at status_updater_async.py line 497).
  Scope: Fallback uses bounded semaphore, runs fully async, only fires after
  N consecutive empty cycles.
  Dependencies: PR0034h complete.
  Out of scope: permission-denied isolation, quarantine, retry backoff.

PR0047 — Device Runtime and Daily Energy Metrics
  Root cause: Daily runtime and energy computed in-device but not exposed through
  typed snapshot.
  Scope: RuntimeLoadState and LoadControlSnapshot gain today_run_seconds and
  today_kwh fields.
  Dependencies: PR0042.
  Out of scope: Historical energy. TimescaleDB energy tracking.

PR0048 — TimescaleDB History Foundation and Read API
  Root cause: TimescaleDataCollector writes data but no read API exists.
  Scope: Bounded ingestion schema. Read-only query API under /control/history
  with metric_name, from_ts, to_ts, aggregation, resolution. Auth-protected.
  Dependencies: PR0038.
  Out of scope: Historical chart rendering. Downsampling. Retention policy.

PR0049 — Historical Charts, Retention and Downsampling
  Root cause: TimescaleDB data but no browser charts, retention policy, or
  downsampling.
  Scope: History tab renders time-series charts using Canvas/SVG. Configurable
  retention. Downsampling for >7d queries.
  Dependencies: PR0048.
  Out of scope: Advanced chart types. Export. Comparison overlays.

Assessment: Fifteen PRs, contiguous range PR0035-PR0049, no missing or
duplicated numbers. Each PR has one narrow root cause supported by repository
evidence. Each PR has explicit scope and out-of-scope boundaries. Dependency
gates are defined.
