GOAL

    Restore the main Dashboard (/) as the pond's operational interface by
    removing the large Winter Intelligence / Grid-Battery Coordination
    diagnostic panel from it, and relocate that complete read-only diagnostic
    panel to the Controls page (/controls), where it is rendered by the
    existing shared renderer and refreshed through the Controls page's own
    polling lifecycle.

    All operational dashboard functionality must remain intact, and all
    Task 0076–0081 safety boundaries must remain unchanged.

SCOPE — AUTHORIZED CHANGES

1. DASHBOARD RESTORATION (app/web/templates/index.html)

    - Remove the entire winter diagnostic panel block
      (id="winter-diagnostics-panel" and all winter-* children) from the main
      Dashboard template.
    - Preserve all existing operational markup: inverter readings and energy
      KPIs, loads table, sensors panel, device controls and modal, navigation,
      warnings strip, and the dashboard-patch.js include.
    - No other dashboard markup is changed.

2. CONTROLS INTEGRATION (app/web/templates/controls.html,
   app/web/static/controls.css)

    - Add the complete winter diagnostic panel to the Controls template,
      including: coordination state, desired output profile, reported output
      priority, charger state / provenance, charge policy, coordination
      history / conflicts, coordination lockout, and an expandable <details>
      block containing DESS receipt, measurement time, persistence, last
      evaluation, diagnostic failure, telemetry, HOLD/BLOCK reasons,
      coordination blockers and missing evidence.
    - Preserve the exact persistent label
      "SHADOW ONLY — NO HARDWARE COMMANDS" and the advisory-versus-observed
      distinction ("no physical inverter switch is claimed").
    - Add only the CSS needed to style the <details> disclosure.
    - Do not add any button, form, input, select, textarea or command
      affordance inside the panel.
    - Do not alter existing charts, time-range selectors, charger history or
      transition tables.

3. SHARED RENDERER REUSE (app/web/static/dashboard.js)

    - Expose the existing renderWinterDiagnostics function as a read-only
      export (window.dessmonitorWinterDiagnostics = { render: ... }) so the
      Controls page can reuse it without duplicating rendering logic.
    - Do not change dashboard polling behavior. On Controls there is no
      #dashboard-content element, so the dashboard's start() returns before
      executePoll(); no competing polling loop is introduced.

4. CONTROLS POLLING AND FAILURE HANDLING (app/web/static/controls.js)

    - Integrate a read-only GET /control/state fetch into the Controls page's
      existing DOMContentLoaded + REFRESH_MS lifecycle.
    - Guard against overlapping requests (winterLoading), use a per-call
      AbortController with a bounded timeout, redirect to /login on 401, and
      render the explicit unavailable state on non-OK or invalid responses.
    - Release the controller and timer in a finally block.
    - Render only through the shared textContent-based renderer.

5. TESTS (tests/test_task0079_ui.cjs)

    - Update the winter panel markup assertions to target controls.html.
    - Add assertions that the panel is absent from index.html and present
      exactly once on controls.html.
    - Add a regression test that the dashboard initialises without any winter
      diagnostic DOM.
    - Add tests that Controls fetches /control/state and renders the panel, and
      that a missing snapshot renders as unavailable.
