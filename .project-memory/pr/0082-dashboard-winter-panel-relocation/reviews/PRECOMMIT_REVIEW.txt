3. JavaScript and polling — VERIFIED

dashboard.js exposes a read-only renderer via
window.dessmonitorWinterDiagnostics = { render: renderWinterDiagnostics }.
On Controls there is no #dashboard-content element, so dom.isAnalyticsPage is
true and start() returns before executePoll()/scheduleRefreshTick(); the
dashboard therefore starts no competing polling loop on Controls. controls.js
integrates the diagnostic fetch into its existing DOMContentLoaded +
REFRESH_MS (60 s) lifecycle, guarded by winterLoading so overlapping calls are
skipped, with a per-call AbortController and a 20 s timeout, a 401 redirect to

unavailable state, and a finally block that clears the timer and releases the
controller. Rendering reuses the textContent-only helpers. The new tests
"controls fetches read-only state and renders the winter diagnostic panel" and
"controls labels a missing snapshot as unavailable" pass.
