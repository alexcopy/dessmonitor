IMPLEMENTATION SUMMARY

run.py changes:
  - Added import: from zoneinfo import ZoneInfo (stdlib, Python 3.9+).
  - Updated _inverter_provider() docstring to document timezone normalization.
  - Added observed_at normalization logic:
    - If dt.timestamp is already ISO-like (contains T, Z, +, or ends with 00:00),
      passes through unchanged.
    - If naive "YYYY-MM-DD HH:MM:SS" string, parses with datetime.strptime and
      localizes to Europe/London via zoneinfo.ZoneInfo("Europe/London").
    - Emits ISO 8601 string with offset (e.g., "2026-07-25T12:00:00+01:00").
    - Falls back to original string on parse errors.
  - All existing inverter fields preserved unchanged.

dashboard.js changes:
  - New: computePowerSeverity(outputPower)
    Pure function. Returns "green" (<=1700W), "amber" (>1700 and <=2600W),
    "red" (>2600W), or "unknown" (null/undefined).
  - New: renderInverterTimestamp(snapshot)
    Reads inverter[0].observed_at, formats via formatLondonTimestamp()
    using toLocaleString("en-GB", {timeZone: "Europe/London"}).
    Sets #inv-timestamp textContent.
  - New: formatLondonTimestamp(isoString)
    Parses ISO 8601, formats to en-GB locale in Europe/London timezone.
    Returns "N/A" for missing/invalid timestamps.
  - New: renderInverterFreshness(snapshot)
    Reads inverter[0].observed_at, computes age via computeInverterFreshness().
    Sets #inv-freshness textContent and className:
      "fresh" → tag is-success is-light (green)
      "stale" → tag is-warning is-light (amber)
      "unavailable" → tag is-light (grey)
  - New: computeInverterFreshness(observedAtStr)
    Client-side computation: age <= 150s → "fresh", <= 600s → "stale",
    > 600s or null → "unavailable".
  - Updated: renderOperatorSummary()
    Now sets dsOutputPower.className with severity class (ds-power-severity-green,

  - Updated: renderSnapshot()
    Calls renderInverterFreshness(snapshot) after renderOperatorSummary.
    Calls renderInverterTimestamp via renderInverterDetail (inline).
  - Updated: cacheDom()

POWER SEVERITY CONTRACT IMPLEMENTED

Thresholds (hardcoded in computePowerSeverity):
  output_power <= 1700   → "green"   → .ds-power-severity-green (#48c78e)
  1700 < op <= 2600      → "amber"   → .ds-power-severity-amber (#946c00)
  output_power > 2600    → "red"     → .ds-power-severity-red (#f14668)
  null / undefined       → "unknown" → plain .ds-compact-value (default color)

Applied only to #ds-output-power element. No other metric receives severity.

TIMESTAMP CONTRACT IMPLEMENTED

Backend (run.py):
  - zoneinfo.ZoneInfo("Europe/London") localizes naive timestamps.
  - Already-ISO strings pass through unchanged.
  - Emits ISO 8601 with timezone offset.

Frontend (dashboard.js):
  - formatLondonTimestamp() uses toLocaleString("en-GB", {timeZone: "Europe/London"}).
  - Two distinct timestamps rendered:
    1. Dashboard snapshot: "Snapshot: <time>" (#snapshot-timestamp, existing)
    2. Inverter timestamp: "Inv time: <time>" (#inv-timestamp, new)
  - Both in Europe/London timezone format.

FRESHNESS CONTRACT IMPLEMENTED

Client-side computation in computeInverterFreshness():
  - observed_at null/empty → "unavailable" (grey)
  - age <= 150s (2.5x inverter poll interval of 60s) → "fresh" (green)
  - 150s < age <= 600s (10x poll interval) → "stale" (amber)
  - age > 600s → "unavailable" (grey)

Rendered as badge in #inv-freshness element (operator summary row).
Uses same tag pattern as sensor freshness for visual consistency.
Computed each dashboard render cycle (5s poll).
