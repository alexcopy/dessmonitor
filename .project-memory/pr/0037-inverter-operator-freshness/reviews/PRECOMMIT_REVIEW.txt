TIMESTAMP ASSESSMENT

Snapshot timestamp (#snapshot-timestamp):
  Source: ControlStateSnapshot.created_at (ISO 8601 UTC)
  Display: "Snapshot: <toLocaleString output>" — existing, unchanged
  Label: "Snapshot:" — existing, unchanged

Inverter timestamp (#inv-timestamp, NEW):
  Source: InverterReadSnapshot.observed_at (ISO 8601 with Europe/London offset)
  Display: via formatLondonTimestamp() using toLocaleString("en-GB",
    {timeZone: "Europe/London"})
  Label: "Inv time:" — in inverter-detail-section
  Default: "N/A" when inverter data absent

Backend normalization:
  run.py _inverter_provider() uses zoneinfo.ZoneInfo("Europe/London") to convert
  naive "YYYY-MM-DD HH:MM:SS" strings to ISO 8601 with offset.
  Already-ISO strings pass through unchanged.
  Verified by Python zoneinfo tests [10]-[11]: BST (July) produces +01:00,
  winter (January) produces +00:00 (GMT).

Two timestamps are clearly distinguished: one labeled "Snapshot" at the top of
dashboard content, one labeled "Inv time" in the inverter detail section.

CONFIRMED: matches PLAN.txt timestamp contract.
