POWER SEVERITY ASSESSMENT

The plan explicitly defines the threshold contract:

Threshold               output_power range      Severity        Visual
<= 1700 W               <= 1700                  green           has-text-success or equivalent
> 1700 and <= 2600 W    > 1700, <= 2600          amber           has-text-warning or equivalent
> 2600 W                > 2600                   red             has-text-danger or equivalent

Thresholds are derived from typical 3-3.5 kVA inverter ratings (1700W ≈ 50%,
2600W ≈ 80%). The severity is applied only to the output power element
(#ds-output-power) via className. No other metric receives severity coloring.

FRESHNESS CONTRACT ASSESSMENT

The plan defines:

Freshness is computed client-side in dashboard.js from inverter.observed_at.

Thresholds (based on 60s inverter poll interval):
- observed_at null or undefined -> "unavailable" (grey badge)
- Current time - observed_at <= 150s (2.5x poll) -> "fresh" (green badge)
- Current time - observed_at <= 600s (10x poll) -> "stale" (amber badge)
- Current time - observed_at > 600s -> "unavailable" (grey badge)

Visual: Reuses existing sensor freshness pattern (tag.is-success.is-light,
tag.is-warning.is-light, tag.is-light). Consistent with the Sensors table.

Freshness is computed each render cycle (5s dashboard poll), no separate timer.
ACCEPTABLE: Explicit, consistent, well-documented.
