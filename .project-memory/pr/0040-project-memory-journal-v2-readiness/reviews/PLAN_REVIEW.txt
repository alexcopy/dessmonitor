REMAINING BLOCKERS
1. Clock skew. JOURNAL_V2_OPERATOR_RUNBOOK.md:288 obtains t_exit using date -u
   on the operator machine; lines 323 and 327 compare it to PostgreSQL's
   xact_start, which uses the database server's clock. For example, if the DB
   clock is two minutes ahead, an actual in-flight cutover transaction begun one
   minute before the client ends has xact_start one minute later than t_exit.
   The drain omits that transaction even if it is waiting for the advisory lock
   or processing a previously sent COMMIT. In the latter case, a subsequent v1
   read can precede that commit and falsely establish non-commit. Capture a
   conservative cutoff from the same authoritative PostgreSQL server after
   independently establishing client termination, or otherwise prove a bound
   that makes clock skew impossible to exclude a relevant transaction; retain
   UNKNOWN if that evidence cannot be obtained.
2. Incomplete process visibility. At lines 279-286 the /proc loop silently
   continues on every OSError reading a cmdline and prints NO_CUTOVER_PROCESS
   if no other match exists. On a system with restricted /proc visibility,
   permissions, or another read error, the cutover process may be alive but
   unreadable. In particular, a process stalled before beginning its transaction
   may start it after the drain and final v1 read. Require positive evidence that
   the recorded invocation has ended, and fail closed when process enumeration
   or relevant cmdline visibility is incomplete; do not treat unreadability as
   process absence. Preserve the backend-drain check after pod deletion/restart.
