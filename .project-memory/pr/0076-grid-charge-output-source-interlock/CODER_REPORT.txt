IMPLEMENTED FUNCTIONALITY

app/control/grid_output_interlock.py (new):
- evaluate_interlock(snapshot, baseline, recent_history, durable_state, *, evaluated_at,
  proposal=None) -> InterlockDecision. No clock reads, no I/O, no device/charger/relay/Tuya imports.
- Reuses the existing pure shadow evaluator app/control/adaptive_output_policy.py
  (evaluate_output_policy, OutputTelemetry, OutputPolicyBaseline, Evidence) for telemetry
  freshness, history coverage, solar classification, demand vs PV, failed-trial and churn
  lockout detection and Line-Mode rebound detection, plus its private segmentation/sag helpers so
  both evaluators classify modes and sag identically. No competing output-control framework.
- Inputs: OutputTelemetry; ChargerObservation (mode, observed_at, provenance DEVICE_READBACK /
  LAST_COMMAND_CACHE / UNKNOWN); ChargePolicyStatus (read-only copy of the charge controller's
  published state); PvContext (curtailment, external controller: ABSENT/PRESENT/UNKNOWN; timezone
  verified); raw output priority (observation only); Tuya managed-load total (diagnostic only,
  never used as demand); DurableInterlockState (PERSISTED / RECONSTRUCTED / UNAVAILABLE); optional
  expiring ShadowProposal (reported only; never changes the baseline). NULL is unknown, never zero.
- Eight states: GRID_RECOVERY_ACTIVE, GRID_RECOVERY_COMPLETE, GRID_OUTPUT_HOLD,
  SOLAR_RETURN_CANDIDATE, BATTERY_RETURN_ELIGIBLE, BATTERY_TRIAL, CHURN_LOCKOUT, FAULT_HOLD.
  Actions: HOLD / ADVISE / BLOCK; ADVISE only for BATTERY_RETURN_ELIGIBLE (enforced in the
  decision constructor).
- Explicit precedence (module docstring and tests): GRID_RECOVERY_ACTIVE (emergency first) >
  FAULT_HOLD > CHURN_LOCKOUT > GRID_RECOVERY_COMPLETE > BATTERY_TRIAL > Line-Mode hold / candidate /
  eligibility. Lower-precedence reasons are still reported, and an active lockout is always carried
  into updated_state even when a fault or recovery state wins.
- Recovery completion requires the policy's own idle/release status (fresh) AND a fresh device
  readback of solar_only. Missing, stale, cached-command or ambiguous charger values never end a
  believed recovery and block optimism (CHARGER_STATE_UNVERIFIED).
- Eligibility requires: Line Mode; base evaluator decision CONSIDER (fresh data, coverage, mains
  dwell, verified current safety, known limits, productive stable solar, fresh forecast); fresh
  solar_only readback; fresh charge policy; known PV context and verified timezone; no lockout; and
  independent reserve evidence — a completed comparable loaded Invert Mode period of at least
  min_battery_dwell_seconds with no fast sag, voltage at or above the approved exit guard and
  discharge current within the approved limit, ending AFTER any later grid recovery or lockout
  expiry. Grid charge current and Line-Mode voltage rebound are never reserve evidence; reported SOC
  is never evaluated.
- Failed trials: a short Invert period with fast sag or exit-guard breach is FAILED_BATTERY_TRIAL ->
  CHURN_LOCKOUT (trial_phase FAILED). Repeated short Line/Invert runs -> CHURN_LOCKOUT via the
  existing transition-rate rule. After a lockout expires, new reserve evidence and mains dwell must
  postdate the expiry (POST_LOCKOUT_EVIDENCE_PENDING).
- Restart: a persisted future lockout is honoured even when the triggering history is absent
  (LOCKOUT_PRESERVED_ACROSS_RESTART); UNAVAILABLE state -> FAULT_HOLD; RECONSTRUCTED state uses the
  supplied history and never yields eligibility when coverage is insufficient. Lockouts are never
  reset by a restart. updated_state is returned for a future adapter to persist (source
  EVALUATOR_OUTPUT); no storage is wired and no schema exists.
- Output separates advisory state from observation: observed_working_mode, observed_charger_mode,
  charger_provenance, output_priority_raw, transition_origin = unknown_external_or_device,
  application_authorized_trial = False, advisory_only = True, command_issued = False (constructor
  rejects any other value).
- Reason codes include all required distinctions: GRID_RECOVERY_ACTIVE / EMERGENCY_RECOVERY_PRECEDENCE
  / GRID_CHARGE_NOT_SOLAR / GRID_RECOVERY_COMPLETE_NOT_ELIGIBILITY (grid recovery), WEAK_SOLAR_SUPPORT,
  LOAD_EXCEEDS_PV / HIGH_MEASURED_LOAD, VOLTAGE_REBOUND_NOT_RECOVERY, CHARGING_SOURCE_UNVERIFIED /
  CHARGER_STATE_UNVERIFIED, INCOMPLETE_TELEMETRY / STALE_TELEMETRY / FUTURE_TIMESTAMP /
  CONTRADICTORY_TELEMETRY, FAILED_BATTERY_TRIAL, CHURN_LOCKOUT, BATTERY_RETURN_ELIGIBLE, plus
  PV_CONTEXT_UNKNOWN, RESERVE_EVIDENCE_MISSING, DURABLE_STATE_UNAVAILABLE and others.
- replay_records(records, *, baseline, source): replays /api/charts/inverter-shaped records
  (time, pv_power_w, battery_voltage, output_power_w, working_mode) in order without filling nulls
  or gaps; per-record label VERIFIED_FROM_EXPORT / UNKNOWN_FROM_EXPORT / SIMULATED_SCENARIO and
  missing fields; counts observed mode changes from working_mode only (independently of any charger
  request) and reports changes across unknown modes separately; lists fields the export does not
  contain (currents, charger, policy, output priority, sun times, device timestamp, curtailment,
  external controller, command history). With those unknown, export results fail closed.

  most recent recovery.

  ADVISE is constructible only for BATTERY_RETURN_ELIGIBLE.
- Emergency charging/recovery is reported with precedence and never delayed or altered; charger
  policy, thresholds and BatteryChargeController are untouched.

- Measured inverter output demand is used; Tuya managed totals are diagnostic only.
- Lockouts survive restart and are never shortened by it.
- Advisory state is kept separate from the observed inverter mode; observed transitions have origin
  unknown_external_or_device.

  behaviour is touched.

FOLLOW-UP CORRECTIONS — INDEPENDENT REVIEW FINDINGS

The four blocking findings from the independent precommit review were corrected in the same
shadow-only scope:

1. Reserve evidence now evaluates only the newest completed Invert segment. A newer segment that
   is too short, below the exit guard, over the approved discharge limit, incomparable in load, or
   shows fast sag invalidates reserve evidence rather than allowing an older segment to be selected.

2. Unknown recovery continuity now fails closed. A missing recovery-in-progress value, an
   unpersisted evaluator-output state, or unreconstructable restart state cannot publish reserve
   evidence or authorize eligibility. A fresh idle policy/readback pair does not manufacture a
   recovery completion timestamp.

3. Replay provenance is explicit. The default source is UNVERIFIED_PROVENANCE. Synthetic,
   imported-unverified, unverified, and independently validated labels are distinct, and only an
   explicit VERIFIED_FROM_EXPORT or INDEPENDENTLY_VALIDATED source can produce a positive provenance
   label for a complete row. No production fields or verification status are fabricated.

4. Charge-policy metadata is validated before eligibility. Missing or non-boolean emergency state,
   missing/unrecognised desired charger mode, and contradictory emergency/state combinations block
   advice. Grid-assisted charging plus voltage rebound remains recovery/non-solar evidence and never
   becomes solar reserve evidence.

shadow-only scope:
