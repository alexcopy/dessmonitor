BLOCKER RESOLUTION

1. Runtime provider ownership and UI path — RESOLVED
   PLAN.txt has a non-conditional allowlist for the full read-only path and
   explicitly specifies:
   run.py -> app/web_runtime_integration.py -> app/web_host.py ->
   app/web_control_state_provider.py -> app/control/runtime_snapshot_adapter.py.
   The winter diagnostics provider is a separate typed provider argument at
   every boundary, is kept out of the generic runtime mapping, and is stored
   only as a display-only block. Generic caller fields including synthetic,
   verified, source, scalar reserve and inspectable records are explicitly
   ignored. The required end-to-end runtime provider/adapter test injects
   synthetic=False and asserts unavailable/unverified reserve and no
   BATTERY_USE_ELIGIBLE result. The plan also requires a Timescale writer
   outage to report persistence unavailable/degraded while preserving only
   explicit receipt-based freshness, never fresh persisted evidence.

2. Solar scheduling authority and freshness — RESOLVED
   Scheduling is bound to the exact
   shared_state["output_shadow_sun_times"] tuple
   (weather_time, sunrise, sunset). The plan requires all values to be
   timezone-aware UTC datetimes, weather_time not later than evaluation time,
   and age within the existing read-only
   OutputPolicyBaseline.forecast_max_age_seconds bound. Missing, malformed,
   stale, naive or timezone-unverified values always select 300 seconds; the
   existing sunrise_hour/sunset_hour defaults cannot select the 900-second
   branch. The listed tests cover the exact tuple, valid day/night behavior,
   stale/naive/missing context and the conservative fallback.

3. Task 0076 current-snapshot identity — RESOLVED
   The plan preserves the committed evaluator and requires recomputation from
   the exact current OutputTelemetry object. Its focused test must assert
   inputs.snapshot.telemetry is snapshot for the valid case, then use a
   different snapshot and assert INTERLOCK_SNAPSHOT_MISMATCH, a non-eligible
   result and no authorization even when a caller-reported interlock claims
   eligibility. Task 0078 implementation files and committed tests remain
   forbidden to modify.

4. Event query boundedness and classification — RESOLVED
   The plan fixes event_kind to exactly mode_transition,
   significant_payload_change and checkpoint; excludes legacy rows without
   event_kind; orders by the existing unique power_mode_events.time DESC; and
   applies SQL LIMIT 100 before rendering. It also requires generic telemetry
   changes not to be presented as ordinary mode transitions and covers the
   fixed query/result contract in tests.
