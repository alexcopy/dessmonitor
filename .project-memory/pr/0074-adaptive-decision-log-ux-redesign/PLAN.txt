IMPLEMENTATION SCOPE (as implemented)
1. Theme. Remove Bulma .box/.title usage on this page. Page styles live in one inline <style> block in the
   template (CSP allows inline styles; a separate stylesheet would require an app/web_host.py allowlist
   change, which is out of scope). Every selector is scoped to .adl/.adl-* or [data-tone]; colours come from
   dashboard.css tokens (--bg, --surface, --surface2, --border, --text, --text-dim, --teal, --amber, --green,
   --red, plus existing --purple and *-dim tokens).
2. Primary decision panel. One prominent panel: decision label (HOLD / BLOCKED / INSUFFICIENT DATA /
   hypothetical proposal / No decision yet / Unavailable), one-line consequence, ONE primary reason, a link to
   the remaining factors, hypothetical-candidate line when present (always non-actionable), last evaluated
   time with relative age, worker status, current threshold only when verified by device read-back (otherwise
   "Not verified"), and an attention line that separates real worker problems from limited evidence.
   The read-only marker "DRY-RUN — NO HARDWARE WRITE" is shown in the header.
3. Primary reason selection. A fixed presentation-only priority order (system/worker problems, data
   freshness/validity, voltage-comparison blockers, limits/configuration, confirmation, unknown codes,
   cycling, provenance caveats). It never changes the recorded codes; all codes stay listed in Technical
   details with the main one marked.
4. Secondary indicators: exactly three — reported mode changes (explicitly "not verified physical
   switching"), unique observations, evidence quality.
5. Timeline: at most five condensed entries by default from actual Journal v2 events (API order, newest
   first). Minor CONFIRMATION_CHANGED / BATTERY_RESPONSE_CHANGED entries yield to meaningful events; adjacent
   identical events are condensed with a count; a stability-only DECISION_CHANGED is labelled "Stability
   changed", never a new decision. A "Full event history" disclosure keeps every original event, its full
   timestamp and payload. Journal v1 states that its event timeline is unavailable.
6. Timestamps: compact local time; full local time, IANA zone, UTC offset and the stored value in the title
   attribute; unparseable values shown verbatim.
7. Technical details (closed): grouped key/value lists — reasons, worker health, evidence and telemetry
   quality, cycling analysis, battery voltage comparison, hypotheses and confirmations, journal storage and
   repetitions — plus nested disclosures for long code lists and the complete raw latest-evaluation JSON.
   All existing scientific and provenance caveats retained.
8. History (closed): range buttons and export inside; decisions table with fixed columns, stacked rows on
   narrow screens; battery tables scroll locally. Export endpoint, parameters and v1-only label unchanged.
9. Error/empty states: explicit "Unavailable" panel with Retry; a failed refresh keeps the last data with a
   "Refresh failed" notice; v2-without-evaluation never falls back to a v1 row.
10. Preserve unchanged: API calls and limits, cursor pagination, generation/stale-response guards, pending
    reset, retries, duplicate guards, deferred History rendering and deferred battery requests, battery
    voltage validity rules, reason fallback for unknown codes.
